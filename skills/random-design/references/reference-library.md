# Reference library workflow

1. Inspect the complete examples in https://xingchenyd.github.io/random-design/showcase/.
2. Obtain 3–5 briefs with generate_reference_briefs. Pass subject, facts, language and count. Preserve supplied wording and data. Use include with count 1 for an explicit direction; use exclude for recently used IDs.
3. Keep each brief's hierarchy: grid, font roles, palette roles, anchor and material. Archived voice/twist fields are not active instructions in random-design. Do not invent or rewrite user facts to satisfy a motif.
4. Build a content-specific page or deck. A brief is not a rendered page. The 20 supplied examples are finished reference implementations, not universal templates for arbitrary content.
5. Present comparable actual renders before choosing. Preserve native text and data in PPTX. A web grid must be adapted to slides with readable sizes and separate page types.
6. For reference pages only, critique_reference_page offers heuristic checks. Its bans must never override the 21 explicitly selected preset aesthetics. A score is not an aesthetic judgment; inspect the actual render on desktop/mobile or every slide.
7. Save the full reference-roll JSON, including constraints and content. Use reproduce_reference_brief with the original ref/constraints/content. Saved bundles from another source revision must not silently claim identical reproduction.

The independent project retains qybaihe's MIT attribution for the imported 40-direction rules and 20 examples. Some styles overlap with the 21 presets; do not market these as 61 distinct styles. Browser reference history avoids the last 15 directions in that browser. CLI reference history is not automatic; the procedural engine has its own portable history.
